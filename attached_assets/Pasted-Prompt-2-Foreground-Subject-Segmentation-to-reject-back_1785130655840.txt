Prompt 2 — Foreground/Subject Segmentation to reject background-only false matches
Feature: Add subject/foreground segmentation as a borderline-rescue-style signal to catch cases where only the background matches but the main subject differs
We've seen cases where a short-clip frame's background (e.g. scenery, smoke, generic environment) matches a movie frame's background well, even though the actual subject in the two frames is completely different (e.g. an added animated character in the short clip vs. nothing/something else in the movie at that matched point) — inflating the match confidence when the core content is actually unrelated.
Task:
Add a new file server/subject-signal.ts that uses a lightweight, self-hosted segmentation model to separate the main subject(s) from the background in a frame. Since our existing MediaPipe integration (@mediapipe/tasks-vision) already includes an ImageSegmenter task with pre-trained models (e.g. the selfie/general-purpose segmentation models), prefer using that over introducing a new framework like Meta's SAM, to avoid adding a new heavy dependency — only reach for a SAM-style model if MediaPipe's segmentation genuinely isn't sufficient for general (non-person) subjects after testing.
Expose a function getSubjectMask(imageData): { hasSubject: boolean, maskCoverage: number, subjectRegion: BoundingBox } that returns whether a distinct foreground subject was detected, how much of the frame it covers, and its bounding box.
Use this only as part of the existing borderline-confidence enhancement pass (enhanceBorderlineSegments in server/matching-engine.ts, the same 55–75% confidence range used for the face/hand/object/keypoint signals) — not on every frame. For a borderline segment, compute the subject mask for both the short-clip frame and the movie frame, then compare the masked (subject-only, background-excluded) region's similarity separately from the background region's similarity.
If the subject-region similarity is low while the overall/background similarity is what pushed the score into the borderline range, this is a signal that the match is likely a background-only false positive — apply a confidence penalty (unlike the other three borderline signals, which only ever add confidence, this one can specifically flag "reject" when the foreground content clearly disagrees, since a differing main subject is strong evidence against a genuine match).
If no clear subject is detected in either frame (e.g. a pure landscape/background shot with nothing distinct), skip this signal entirely and defer to the existing signals — don't penalize legitimately subject-less scenes.
Log clearly when this signal downgrades a segment, e.g. [SubjectSignal] Borderline match at frame X downgraded — background similarity high but subject regions disagree (subjectSim=Y%).
Strict constraints:
Unlike the additive-only face/hand/object/keypoint signals, this signal is explicitly allowed to reduce confidence on a borderline segment — but it must still only operate within the existing 55–75% borderline range, never touching segments already confidently matched or confidently rejected outside that range.
Confirm the chosen segmentation approach is fully self-hosted, free, and has no runtime external API dependency, consistent with our other signals.
Report the Docker image size and processing time impact, scoped only to the borderline second-pass (same reporting pattern as the other signals).
Test with existing test files to confirm no regression, and if possible construct/identify a test case similar to the reported issue (distinct foreground subject differs while background matches) to validate this actually catches that case.
